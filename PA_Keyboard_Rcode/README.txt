The code implements PA-Keyboard, an exposure-guided pediatric dose-finding
method that borrows information from adult trials. It compares PA-Keyboard
with Keyboard and PA-CRM in ten simulation scenarios (E0-E3, M1-M2, L1-L2,
and S1-S2) and conducts the prespecified sensitivity analyses.

The scripts generate manuscript Tables 1-4, supplementary Tables B-1 to B-5,
and Figures 1-2. All patient observations are simulated; no external patient
dataset is required. Scenario truths are defined in R/01_design.R, and the
shared potential outcomes are generated by functions in R/05_simulation.R.


2. Software requirements
------------------------
R is required. RStudio is recommended for running the supplied project.
The required add-on packages are openxlsx, dplyr, tidyr and ggplot2.
The parallel package is distributed with R.

Install the add-on packages before running the scripts:
  install.packages(c("openxlsx", "dplyr", "tidyr", "ggplot2"))

Execution environment:
  Operating system: Windows 11 x64
  R version:        4.5.0

Required add-on package versions:
  openxlsx  4.2.8.1
  dplyr     1.2.1
  tidyr     1.3.2
  ggplot2   4.0.2

Computational resources and approximate run time:
  Processor/RAM:    13th Gen Intel Core i7-13700; 32 GB RAM.
  Worker processes: 4 (n_workers in run_analysis.R).
  Simulation time: Approximately 1.5 hours.

Reproduction check:
  The full study, with 5,000 replications per scenario and all prespecified
  sensitivity analyses, was completed. The authors checked the generated
  results against the manuscript tables and figures and confirmed agreement.

4. Reproducing the results
-------------------------
Extract the complete archive without changing its folder structure. Open
PA_Keyboard.Rproj in RStudio, then open the required script and click Source.

4.1 Preliminary checks

Open test_analysis.R and click Source to run the small checks. To additionally
compare serial and two-worker parallel execution, set check_parallel <- TRUE
in that file before running it. These checks do not reproduce the full study.

4.2 Quick trial run

In Section 1 of run_analysis.R, set:
  n_sim     <- 10L
  n_workers <- 1L
  output_dir <- "results_quick"
  resume     <- FALSE

Click Source. This executes the study with fewer replications to check the
workflow. These outputs are for testing and must not be used as the manuscript
results. The separate directory prevents mixing quick-run and full-study files.

4.3 Full simulation study

In Section 1 of run_analysis.R, use:
  n_sim     <- 5000L
  n_workers <- 4L
  output_dir <- NULL
  resume     <- TRUE

Click Source to execute the ten main scenarios, the sensitivity analyses,
and table/figure generation. n_sim is the number of replications per scenario;
n_workers controls parallel execution and may be adjusted to available resources.
No repeated manual changes to individual scenarios are needed.

The default master seed is 24082026, specified in R/01_design.R. The simulation
engine derives random streams by scenario, replication and outcome domain.
Retain the study seed and design settings when reproducing the reported results.

4.4 Project and output paths

With PA_Keyboard.Rproj open, project_dir <- "." refers to the project root.
output_dir <- NULL saves results in the project's results/ directory. A relative
output_dir, such as "results_quick", is resolved against the project root.

If the project file is not used, set project_dir in the script to the extracted
project directory. An independently chosen output directory is also supported:
  project_dir <- "D:/Research/PA_Keyboard"
  output_dir  <- "E:/PA_Keyboard_results"

These paths are examples; replace them with directories on the local computer.
For command-line execution, change to the project directory and run:
  Rscript test_analysis.R
  Rscript run_analysis.R

6. Saved results and regeneration
---------------------------------
6.1 Availability of saved results

The archive includes both the analysis code and completed simulation results,
including the RDS records needed to regenerate the tables and figures.
No separate download is required. Extract the complete archive before use.

6.2 Regenerate tables and figures

A completed PA_keyboard_ETOVL_formal_full_compact_v03.rds is required.
Use the completed RDS file included in the archive.

Open render_results.R, set project_dir to the code project and output_dir to
the directory containing that RDS file, then click Source. This recreates both
Excel workbooks and Figures 1-2 without rerunning the simulations. Output files
with the same names are overwritten; the analysis RDS is retained.

6.3 Resume or rerun simulations

With resume <- TRUE, run_analysis.R reuses compatible completed scenario
checkpoints and runs the remaining scenarios. Resumption is at the scenario
level, not at an individual replication within an unfinished scenario.

To rerun all simulations, set resume <- FALSE. Use a separate output directory
when retaining an earlier set of results. Changes to simulation settings can
invalidate saved checkpoints and require the affected scenarios to be rerun.
